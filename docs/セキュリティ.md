# セキュリティ

開発手順 Phase 19 の監査記録と、実装している対策。

## 1. 秘密情報

| 項目 | 状態 |
| --- | --- |
| `.env` を Git 管理しない | `.gitignore` で除外。全履歴を検索し、実際のAPIキーが入っていないことを確認済み |
| APIキーをフロントエンドへ渡さない | フロントの設定は `NEXT_PUBLIC_API_BASE_URL` のみ。ビルド成果物にキーが含まれないことを確認済み |
| ソースへの直接記述 | 設定は `app/core/config.py` の環境変数経由のみ |

LLM プロバイダの呼び出しは Backend でのみ行う。フロントから LLM API を直接叩く経路は無い。

## 2. LLM の権限制御（要件定義書 32.2）

```
ユーザー → LLM → Tool Calling → FastAPI → Service → Repository → PostgreSQL
```

- LLM が実行できる操作は `ToolRegistry` に定義したものだけ。
- **Tool は必ず既存の Service を呼ぶ。** ToolRegistry が直接DBを触っていないことを
  テストで検証している（`test_llm_tools_cannot_reach_the_database_directly`）。
- 承認が必要な操作（削除・一括変更・分解・自動配置）は、LLM が単独で実行できない。
  `exposed=False` のツール（`apply_schedule` / `apply_reschedule`）は LLM に提示すらしない。

## 3. LLM の出力の検証（要件定義書 32.3）

Tool の引数は Pydantic で型・日時・範囲を検証してから Service に渡す。
不正な場合は例外にせず、エラー内容を LLM に返して修正させる。

検証しているもの: 型 / 日時の形式 / 数値の範囲 / 文字数 / 配列の要素数 / ID の存在と所有者。

## 4. 権限分離

全ての Repository の問い合わせに `user_id` 条件を入れている。
他人のデータは 403 ではなく **404** を返す（存在の有無を漏らさないため）。

- 監査で `recent_messages` に所有者条件が無いことを発見し、修正した。
  呼び出し側で確認済みでも、Repository 側でも絞る（将来の呼び出しで漏れないように）。

## 5. SQL インジェクション

SQLAlchemy の式言語のみを使用し、文字列連結でSQLを組み立てている箇所は無い
（監査で確認済み）。生SQLは死活確認の `SELECT 1` のみ。

## 6. 入力値の検証

- 全ての入力スキーマで文字列に長さ上限を設定。
  `description` はDBの型が無制限（Text）のため、入口で 5000 文字に制限している。
- リクエスト本文は 1MB まで。Pydantic の検証は本文を読み込んだ後に効くため、
  その手前でミドルウェアが落とす。

## 7. CORS

```python
allow_origins=settings.cors_origin_list   # 既定は http://localhost:3000
allow_credentials=False                   # Cookie を使っていないため
allow_methods=["GET", "POST", "PATCH", "DELETE", "OPTIONS"]
allow_headers=["Content-Type"]
```

認証（Phase 16）で Cookie を使うようになったら `allow_credentials` を見直す。

## 8. 危険操作の確認（要件定義書 24）

| 分類 | 操作 | 実装 |
| --- | --- | --- |
| 確認不要 | 検索・作成・完了 | そのまま実行 |
| 確認必須 | 削除・タスク分解・自動配置・再配置 | `pending_action` を返し、承認後に実行。引数はそこで再検証 |

通常UIからの削除も確認ダイアログを挟む。

## 9. 残っている課題

- **認証が無い**（Phase 16）。現在は固定の既定ユーザーで動作する。
  `get_current_user` 1箇所を差し替えれば認証に移行できる構造にしてある。
- **レート制限が無い。** `/chat` は LLM を呼ぶため、公開時は制限が必要。
- ログにツール呼び出しの引数（タスク名など）が出る。個人利用では問題ないが、
  共有環境では出力先に注意する。
- Python 側の依存パッケージ脆弱性スキャンは未導入（npm 側は `npm audit` で 0 件）。
