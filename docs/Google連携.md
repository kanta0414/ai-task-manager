# Google カレンダー連携の設定

連携すると、**Google 側の予定も「埋まっている時間」として扱い**、空き時間の検索と
自動スケジューリングがそれを避けるようになる。

連携しなくてもアプリは通常どおり動作する（認証情報が未設定なら機能自体が表示されない）。

## この連携で取得するもの

**予定のタイトルや参加者は取得しない。** Google の freeBusy API を使い、
「いつ埋まっているか」の時間帯だけを受け取る。要求する権限も読み取り専用。

| 権限 | 用途 |
| --- | --- |
| `calendar.readonly` | 埋まっている時間帯の取得 |
| `userinfo.email` | どのアカウントと連携中かを画面に表示するため |

## 先に知っておくこと：テストモードでは7日で切れる

公開ステータスが「テスト中」の OAuth クライアントが発行する更新トークンは、
**7日で失効する**（`userinfo` 系だけを要求する場合を除く。この連携は
`calendar.readonly` を含むため対象になる）。

つまり個人利用のままだと、**週に一度つなぎ直す**必要がある。
切れた場合は画面上部に「連携が切れました」と表示され、「つなぎ直す」ボタンが出る。

恒久的に使うにはアプリの公開（審査）が必要だが、個人のポートフォリオ用途では
テストモードのままで問題ない。

## 手順

Google Cloud コンソールの OAuth まわりは「**Google Auth Platform**」に再編されている。

### 1. プロジェクトを作る

1. https://console.cloud.google.com/ を開く
2. 上部のプロジェクト選択 →「新しいプロジェクト」→ 任意の名前で作成

### 2. Calendar API を有効にする

1. 「API とサービス」→「ライブラリ」
2. 「Google Calendar API」を検索して「有効にする」

### 3. Google Auth Platform を初期設定する

「Google Auth Platform」を開くと
**「Google Auth Platform はまだ構成されていません」** と表示される。
**「スタートガイド」** をクリックして、次の4段階を進める。

| 段階 | 入力 |
| --- | --- |
| アプリ情報 | アプリ名（例: `AI Task Manager`）／ユーザーサポートメール |
| 対象 | **外部** |
| 連絡先情報 | 通知を受け取るメールアドレス |
| 完了 | ポリシーに同意 → 「作成」 |

### 4. テストユーザーを追加する

1. 左メニューの **「対象」**
2. 「テストユーザー」→「ユーザーを追加」
3. 自分の Google アカウントのメールアドレスを入力 → 保存

ここに登録したアカウントだけが連携できる。

### 5. スコープを追加する

1. 左メニューの **「データアクセス」**
2. 「スコープの追加または削除」
3. 次の2つを選ぶ
   - `.../auth/calendar.readonly`
   - `.../auth/userinfo.email`
4. 「更新」→「保存」

`calendar.readonly` は「機密性の高いスコープ」に分類される。
テストユーザーとして使う分には審査なしで利用できる。

### 6. OAuth クライアントを作る

1. 左メニューの **「クライアント」**
2. 「クライアントを作成」
3. アプリケーションの種類: **ウェブアプリケーション**
4. **承認済みのリダイレクト URI** に次を追加

   ```
   http://localhost:8000/integrations/google/callback
   ```

5. 作成後に表示されるクライアントIDとシークレットを控える

### 7. アプリに設定する

`backend/.env`:

```
GOOGLE_CLIENT_ID=発行されたクライアントID
GOOGLE_CLIENT_SECRET=発行されたシークレット
GOOGLE_REDIRECT_URI=http://localhost:8000/integrations/google/callback
FRONTEND_BASE_URL=http://localhost:3000
```

バックエンドを再起動すると、画面上部に「Google カレンダー」の連携ボタンが現れる。

## 仕組み

```
画面「連携する」
  → GET /integrations/google/authorize   同意画面のURLを受け取る
  → Google の同意画面
  → GET /integrations/google/callback    認可コードを受け取る
  → トークンを暗号化して保存
  → 画面へ戻る
```

- `state` には**署名付きの短命トークン**を入れる。これが無いと、細工した
  コールバックを踏ませて別アカウントを紐づけられてしまう（CSRF）。
- 保存する refresh token は **SECRET_KEY から導いた鍵で暗号化**する。平文では置かない。
- アクセストークンの期限が近ければ、取得時に自動で更新する。
- 更新に失敗した場合（テストモードの7日失効など）は**再連携が必要だと記録**し、
  画面につなぎ直しのボタンを出す。黙って無視しない。
- **Google 側が落ちていても内部の空き時間計算は動く**（取得失敗時は外部の予定を
  考慮しないだけで、機能全体は止めない）。

## うまくいかないとき

| 症状 | 確認すること |
| --- | --- |
| 同意画面で「アクセスをブロック」と出る | 「対象」のテストユーザーに自分のアカウントを追加したか |
| `redirect_uri_mismatch` | 「クライアント」のリダイレクトURIが `.env` の `GOOGLE_REDIRECT_URI` と完全一致しているか（末尾スラッシュも含めて） |
| 連携ボタンが出ない | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` を設定してバックエンドを再起動したか |
| 急に予定が考慮されなくなった | テストモードの7日失効。「つなぎ直す」を押す |

## 解除

画面の「解除」を押すと、保存したトークンを削除する。
Google 側のアクセス権も取り消す場合は、
https://myaccount.google.com/permissions から削除する。

## 制限

- 現在は**読み取りのみ**。アプリで作った予定を Google 側へ書き出す機能は無い。
- 対象は主カレンダー（primary）のみ。
