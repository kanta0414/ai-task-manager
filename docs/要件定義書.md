# AIタスク・スケジュール管理ツール

## 要件定義書 v2.0

**プロジェクト名:** AI Task Manager（仮称）
**対象:** 個人利用・ポートフォリオ公開
**開発形態:** Webアプリケーション
**主要コンセプト:** 通常UIと自然言語LLMの両方から操作できるタスク・スケジュール管理システム

---

# 1. プロジェクト概要

## 1.1 背景

一般的なタスク管理ツールでは、ユーザー自身がタスクの登録、編集、削除、カレンダーへの予定登録などを個別に操作する必要がある。

本システムでは、従来型のGUI操作に加えてLLMを操作インターフェースとして導入する。

ユーザーは、

* 従来通り画面上のUIを操作する
* LLMに自然言語で指示する

という2つの方法から自由に操作方法を選択できる。

---

# 2. システムの目的

本システムは、ユーザーのタスク・予定・スケジュールを一元管理し、以下の2つの操作方式を提供する。

### 操作方式A：通常UI

ユーザー自身が、

* ボタン
* フォーム
* カレンダー
* ドラッグ＆ドロップ
* タスク一覧

などを使用して操作する。

### 操作方式B：LLM

ユーザーが自然言語で、

> 「明日の14時から2時間、ESを書く予定を入れて」

> 「今週締切のタスクを空いている時間に自動で配置して」

などと指示し、LLMを介してシステムを操作する。

---

# 3. 基本コンセプト

## 3.1 LLMは必須ではない

本システムにおいてLLMは必須の操作手段ではない。

LLMを利用できない場合でも、

**タスク管理・カレンダー管理の基本機能をすべて通常UIから利用可能**

とする。

---

## 3.2 LLMとUIは同じデータを操作する

通常UIとLLMで別々のデータを管理しない。

```text
             ┌──────────────┐
             │   PostgreSQL │
             └──────┬───────┘
                    │
             共通データモデル
                    │
          ┌─────────┴─────────┐
          │                   │
     通常UI操作             LLM操作
          │                   │
      React/Next.js       Tool Calling
```

例えば、

### UI

ユーザーが「ES作成」を登録

↓

### LLM

> 「ES作成の期限はいつ？」

↓

登録済みの「ES作成」を取得して回答する。

逆に、

### LLM

> 「明日18時に企業研究を入れて」

↓

予定が作成される。

↓

### UI

カレンダー上に「企業研究」が表示される。

# 17. Tool Calling

LLMがデータベースを直接操作することは禁止する。

以下の構造とする。

```text
ユーザー
 ↓
LLM
 ↓
Tool Calling
 ↓
FastAPI
 ↓
Service Layer
 ↓
Repository
 ↓
PostgreSQL
```

例えば、

> 「明日の14時からESを2時間やる予定を入れて」

↓

LLM：

```json
{
  "tool": "create_event",
  "arguments": {
    "title": "ES作成",
    "start": "2026-09-21T14:00",
    "end": "2026-09-21T16:00"
  }
}
```

↓

FastAPIが検証

↓

DBへ登録。

# 18. 自動スケジューリング

本システムの主要AI機能とする。

ユーザーが、

> 「今週中にこのタスクを全部終わらせたい。空いている時間に予定を組んで」

と指示した場合、

1. 未完了タスクを取得
2. タスク期限を取得
3. 優先度を取得
4. 所要時間を取得
5. カレンダーを取得
6. 空き時間を取得
7. スケジュールを生成
8. ユーザーへ提案
9. 必要に応じて予定を登録

する。

---

# 19. 自動スケジューリングの確認

大量の予定変更については、即時反映ではなく、

```text
以下のように変更します。

9/21
14:00〜16:00 ES

9/22
10:00〜12:00 企業研究

9/23
15:00〜17:00 SPI

この内容で予定を変更しますか？

[実行] [キャンセル]
```

と表示する。

---

# 20. タスク分解

LLMによって大きなタスクを複数の小タスクに分解できる。

例：

> 「10月1日までにESを完成させたい。必要な作業に分解して」

↓

```text
ES作成
├─ 企業研究
├─ 志望動機作成
├─ ガクチカ作成
├─ 自己PR作成
├─ 全体編集
└─ 最終確認
```

ユーザーの承認後にタスクとして登録できるものとする。

---

# 21. 未完了タスクの再スケジューリング

例：

> 「今日終わらなかったタスクを明日以降に組み直して」

システムは、

* 未完了タスク
* 期限
* 優先度
* 所要時間
* カレンダーの空き時間

を考慮して新しいスケジュールを提案する。

# 22. 会話コンテキスト

LLMは直前の会話内容を参照できる。

例えば、

ユーザー：

> 「明日の企業研究を18時からにして」

AI：

> 「18時から20時に変更しました。」

ユーザー：

> 「やっぱり19時からにして」

この場合、直前の「企業研究」を対象として認識できる。

---

# 23. 自然言語による曖昧な操作

以下のような表現にも対応する。

```text
「それを明日にして」
「さっきの予定を削除して」
「そのタスクを来週にして」
「この予定を2時間後ろにして」
「今日の予定を整理して」
```

LLMは会話履歴およびシステム上のデータを利用して対象を特定する。

対象を一意に特定できない場合は、ユーザーへ確認する。

# 24. 操作確認ポリシー

## 確認不要

* タスク検索
* 予定検索
* タスク作成
* 情報表示
* タスク完了

## 確認を推奨

* タスク削除
* 予定削除
* 複数予定の変更
* 大量タスクの変更

## 確認必須

* 全予定削除
* 複数日の予定を大幅に変更
* 大量データ削除

# 39. 最終的なプロダクト像

最終的には、

> **「普通のタスク管理アプリとしても使えるが、必要なときはLLMに話しかけるだけで、タスク・カレンダー・スケジュール全体を操作できる」**

システムを目指す。

例えばユーザーは、

> 「今日のタスクを教えて」

> 「明日の14時からESを2時間入れて」

> 「企業研究を明後日に移して」

> 「今週締切のものを全部教えて」

> 「これらを今週中に終わらせられるように予定を組んで」

> 「今日終わらなかったものを明日以降に再配置して」

> 「来週は忙しいから、重要度の低いタスクを後ろにずらして」

といった指示を自然言語で実行できる。

一方で、LLMを使用せず、

* タスクフォーム
* タスク一覧
* カレンダー
* ドラッグ＆ドロップ
* 編集・削除ボタン

などの通常UIだけでも、同じデータを完全に管理できるものとする。

本システムの中核は、

**「通常UI」と「LLM」の2つの操作経路を、共通のBackend・Service・データモデルに統合すること**

とする。
