# 1. 開発方針

本システムは、以下の順番で段階的に実装する。

```text
Phase 0
開発環境構築
      ↓
Phase 1
DB・データモデル
      ↓
Phase 2
FastAPI・CRUD API
      ↓
Phase 3
Next.js・通常UI
      ↓
Phase 4
カレンダー機能
      ↓
Phase 5
LLM基盤
      ↓
Phase 6
LLM Tool Calling
      ↓
Phase 7
AIによるタスク・予定操作
      ↓
Phase 8
AIスケジューリング
      ↓
Phase 9
非同期処理・自動化
      ↓
Phase 10
品質改善・公開
```

重要なのは、**Phase 4まで完成すればLLMなしでも一つのタスク管理アプリとして完成する**こと。

その後にAI機能を追加する。

# 26. 最も重要な設計ポイント

このプロジェクトでは、**LLMそのものよりBackend設計が重要**になる。

避けるべき構造：

```text
ユーザー
 ↓
LLM
 ↓
直接DB操作
```

推奨構造：

```text
ユーザー
 ↓
LLM
 ↓
Tool Calling
 ↓
FastAPI
 ↓
Service Layer
 ↓
Repository
 ↓
PostgreSQL
```

通常UIも、

```text
Next.js
 ↓
FastAPI
 ↓
Service Layer
 ↓
Repository
 ↓
PostgreSQL
```

とする。

つまり、

**UIとLLMが同じService Layerを利用する**

構造にする。

# 28. 最終的な開発目標

最終的には、

> **「通常のタスク管理アプリ」＋「LLMを利用したAIエージェント」**

を一つのシステムにする。

ユーザーは、

```text
普通にクリックして操作する
            │
            ├─────────────┐
            │             │
        タスク管理      カレンダー
            │             │
            └──────┬──────┘
                   │
              AI Assistant
                   │
            自然言語で操作
                   │
          ┌────────┼────────┐
          │        │        │
       検索      作成      編集
          │        │        │
          └────────┼────────┘
                   │
             自動スケジュール
                   │
          ┌────────┼────────┐
          │        │        │
        空き時間  タスク分解  再配置
```

という構造を目指す。

**「AIがないと使えないアプリ」ではなく、「通常のアプリとして完成しており、AIを使うと操作方法が自然言語に拡張されるアプリ」**として設計する。
